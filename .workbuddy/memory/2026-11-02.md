# 第32轮（2026-11-02/03）：售卖空间时间点查询纯计划仲裁——废除默认空间机制

## 需求
售卖空间查询某时刻数据：信息来源于空间计划的创建——某时刻已发布且生效中的空间计划创建出的售卖空间；多计划时按优先级降序、同优先级后创建优先。用户确认：**无计划命中的 fn 不展示（「没有设置默认这一说」）**；列表按时刻过滤（只显示该时刻生效计划创建的空间）。

## 实现
- **effectiveSpaceAt 重写（纯计划仲裁）**：候选=published 且 effStart≤t≤effEnd 且 fnSpaces[fn] 空间存在的计划；排序 `(b.priority-a.priority)||(seqOf(b)-seqOf(a))`；无命中返回 {key:'',source:'',plan:null}。currentSpaceOfFn 保留为 delegate 别名（调用点免爆改）。nextSpaceSwitchOfFn 不变（t 后首个改变该 fn 空间的已发布计划）。
- **默认机制全删**：defaultFnSpaceMap/fnSpaceMap/setSpaceActive/「默认」徽标/设为默认操作列；快照链路（snapshotCurrentProduct/productDataOf/openDetailByCode/submitProduct）删 fnSpaceMap 字段。
- **renderSpaceTab 重写**：按 effectiveSpaceAt 过滤，每 fn 至多一行生效空间，无命中 fn 不展示；无任何命中空表提示「该时刻无生效中的售卖空间」；表头 6→5 列（删操作列，min-w 700px）。行内标注：胜出计划（名+起日+优先级）+ 未来切换预告（amber）。
- **切换预告真 bug 修复**：原 aheadExtra 条件 `switchAhead[fn].fnSpaces[fn]===k` 与 nextSpaceSwitchOfFn 的 `!==cur` 过滤矛盾=死代码；改为该 fn 有预告即挂当前生效行（只显示日期+计划名，不出现未来空间名，避免污染按时刻过滤语义）。
- **mock 补常驻计划**：全商品补常规计划（vtpm 三商品 ''→sp1 priority 100；glm4 idx0 input→sp2/output→sp4/cache→sp5）+双11 idx1 input→sp3 priority 500 降至第二位；pre 常驻计划 pending_publish（演示空表态）。
- SU 弹窗装载：effectiveSpaceAt 无回退显式 ||；池内回退 `effectiveSpaceAt(fnKey).key || spKeys[0]`。
- 空间计划弹窗引导文案改为新仲裁口径。
