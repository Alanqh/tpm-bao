# 第33轮（2026-11-03）：删上架状态徽标 + 列表 Tab 改在售/禁售 + 文案精简

## 需求
①商品详情页右上角不留上架状态标识；②售卖单元创建=纯前端逻辑——只有真的为该单元创建了售卖计划，单元才真正创建进后端数据库；商品列表页改为在售/禁售两个 Tab；③列表页不要额外文字说明。

## 实现
- **删 #detail-status 徽标**：详情页头部右侧只剩编辑锁 bar + 返回按钮；refreshProductBadge 保留函数（元素缺失静默 return）防调用点报错，徽标文案改「在售/禁售」（永不实际渲染）。productIsListed 保留供 openPendingDetail 兼容入口。
- **列表 Tab 改制**：已上架/未上架 → 在售/禁售；默认 Tab 从未上架改为在售（#top-tab-listed 初始不隐藏 + active 类移位）。Tab 语义=售卖单元状态直查（在售 Tab=单元在售行；禁售 Tab=单元禁售行，含无计划草稿单元/计划未生效/单元下架）——与既有 renderListed/renderPending 逻辑天然一致，无需改数据层。
- **第2条的模型说明**：单元创建本来就只写页面内 saleUnits（无计划即禁售、出现在禁售 Tab、可删除）——语义上已是「纯前端草稿，创建售卖计划才真正生效」，本轮通过 Tab 语义显性化，无需数据层改动。
- **文案清理**：列表页标题下说明文字删除；售卖计划创建页「只为已上架售卖单元逐个配置」「请为已上架售卖单元 XX …」「暂无已上架售卖单元（请先在区块2勾选并设为「上架」）」全改为「本计划上架」口径；详情页头部说明保留（未要求删）。
- 页面上「已上架/未上架/待上架」UI 文案清零（仅剩 JS 历史注释，7 处，不影响展示）。
