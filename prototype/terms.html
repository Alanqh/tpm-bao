预留 vTPM 购买须知

请您在购买前仔细阅读以下规则。提交购买意向即视为您已理解并同意相关内容。

适用范围：本须知适用于通过官网直销渠道购买的预留 vTPM 资源包，包括售卖规则、SLA 承诺、模型更换及退款等事项。

购买规则

1. 售卖规格

  • 售卖时长：可选 30 天、60 天、90 天、120 天、150 天、180 天，暂不提供小时/天档或超过 180 天的长周期售卖。
  • 起购数量：10 万 vTPM；单用户单次购买范围为 10 万 ~ 100 万 vTPM，步长 10 万。
  • 模型绑定：购买时必须选择具体 model name，资源按模型强隔离。

2. 订单与库存

  • 当前一期走官网飞书表单申请 + 销售跟进 + 线下合同流程，后台通过飞书表格配置购买记录。
  • 订单成立前需完成资源锁定校验，库存不足时订单不成立，可选择候补或替代模型。
  • 资源按先到先得原则分配；销售可为企业客户锁库存，锁库存额度由后台配置。

3. 续约规则

  • 在有效预留 vTPM 存续期且 SKU 售卖窗口期内，用户可任意续约。
  • 下单时可勾选自动续约；续约通知节奏为到期前 T-7、T-3、T-1。
  • 到期日超过停售日期的续约不被接受。

4. 试用与退订

  • vTPM 库存稀缺，暂不开放普遍免费试用。
  • 销售可针对企业客户申请必要代金券抵扣，但不设计普遍机制。

SLA 保障与赔付规则

4.1 SLO 承诺

  • vTPM 速率：每分钟可消耗 N vTPM（N = 购买量），时间粒度为自然分钟，不承诺瞬时峰值。
  • 延迟：P95 TTFT、P95 TPOT 分钟级承诺，具体阈值以对应模型服务等级协议公示为准。
  • 可用性：按自然分钟统计，若该分钟内请求全部失败（5xx/超时），则标记为 C 类违约分钟。
  • 折算系数公开透明、可实时试算；已售 vTPM 包的折算系数一经售出即绑定该订单，原则上保持不变。

4.2.1 数据口径

所有判定均基于自然分钟窗口统计。

类别事件判定
A 类vTPM 速率违约某一自然分钟内，用户实际请求消耗 vTPM ≤ 购买量，但被限流/拒新
B 类延迟违约某一自然分钟内 P95 TTFT 或 P95 TPOT 超承诺阈值
C 类可用性违约某一自然分钟内请求全部失败（5xx/超时）

1. vTPM 速率违约分钟计算

  • 客户 API 请求中指定 model_name 关联的vTPM 包的额度之和，即平台需要保障的 vTPM 阈值。
  • 在自然分钟内，若客户实际消耗 vTPM 小于等于保障值，但其请求遇到 429 限流，则该请求为 A 类违约请求。
  • 若该自然分钟内 A 类违约请求数大于 3，且 A 类违约请求占比超过 10%，则该分钟被标记为 A 类违约分钟。

2. 延迟违约分钟计算

  • 在自然分钟内，P95 TTFT 超过承诺阈值，或 P95 TPOT 超过承诺阈值，则该分钟被标记为 B 类违约分钟。

3. 可用性违约分钟计算

  • 在自然分钟内，请求全部失败（5xx 或超时），则该分钟被标记为 C 类违约分钟。

4.2.2 SLA 赔付规则

某个自然分钟，不论发生哪类违约，均计入违约分钟。

累计违约分钟/月赔付比例附加权
≤ 3 分钟0%容忍窗口
4–30 分钟10%—
31–120 分钟30%—
> 120 分钟100%触发退出权，进入协商流程
  • 赔付基数：当月该预留 vTPM 包已付预留费（不含按量消费）。
  • 同一自然分钟内发生多类违约，只计 1 个违约分钟。
  • 触发退出权后，双方进入协商流程，协商结果以最终协议为准。

4.2.3 用户可见监控数据

1. 监控趋势

  • 按自然分钟统计的 vTPM 实际消耗趋势。
  • 按自然分钟统计的 P95 TTFT 趋势。
  • 按自然分钟统计的 P95 TPOT 趋势。
  • 按自然分钟统计的 5xx 请求数趋势。

2. 事件记录

  • 违约事件：某个自然分钟被标记为违约分钟时生成，写明违约类别、具体指标及判定详情。
  • 正常限流事件：某个请求发生时其实际消耗 vTPM 已超过已购买量，被限流时生成。

4.3 维护与申诉

  • 维护窗口提前 7 天通告，窗口内不计违约。
  • 上游故障（GPU 宕机等）仍算违约，可用不可抗力条款封顶赔付。
  • 用户可在违约事件推送后 30 天内申诉；平台日志缺失时默认采信用户申诉。

模型更换规则

1. 合约期内原则禁止更换 model name

  • 预留 vTPM 购买时已绑定具体 model name，合约期内不支持直接切换模型。
  • 平滑升级的模型若复用已有 model name，对用户无感知，不视为更换。

2. 确需更换的处理方式

  • 用户需走客服工单申请“残值退回 + 自行换购”流程，系统不提供功能性换购入口。
  • 残值 = 购买金额 − 已过时长折算值。
  • 暂不收取手续费；退款通过线下渠道处理。

3. 模型停售与停服

  • 停售：不再售卖新订单，已存续合约不中断；不再接受到期日在停售日期之后的续约。
  • 停服：确需提前停止服务时，平台承担迁移成本并按“平台缺失需强行转换”规则补偿（vTPM 量或时长）。

退款规则

1. 退款触发条件

  • 用户主动退订或换购另一个模型的 vTPM。
  • 发生 SLA 严重违约（> 120 分钟/月）触发退出协商后，确需退费。

2. 残值计算

残值 = 购买金额 − 已过时长折算值
  • 已过时长折算值按自然日比例计算，不足一天按一天计。
  • 赔付场景下按损失填平原则，最大不超过订单金额。

3. 退款路径

  • 一期通过客服工单线下处理，退款以抵扣券或服务费返还形式发放。
  • 退款到账时间以财务流程为准，通常为 7–15 个工作日。

端点绑定说明

购买时提交的 model_name 仅作为需求意向记录，交付时平台会将资源包绑定到您 Pool（project/group）下的对象。交付完成后，请以 /Pool 对象名/model 格式的最终 model_name 发起 API 请求（如 /proj-alpha/deepseek-v4-flash-0731），可在资源包「交付详情」中查看和复制；请求将优先路由至您预留的专属算力资源。

实际消耗 vTPM 超过已购买量时，按购买时选择的超量配置处理：默认超量限流，超量请求返回 429，不产生额外费用，需自行限流、重试或降级；也可选择开启超量路由 Serverless，超量请求将自动路由至相同模型的 Serverless 端点并按量计费。
